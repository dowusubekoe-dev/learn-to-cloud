# What is Git

Git is a version control tool that helps you track changes in your project files.

It lets you save your work over time, go back to older versions, work on different ideas safely, and collaborate with other people.

## Git Basics

| Concept | Beginner-friendly meaning | What it is used for |
| --- | --- | --- |
| **Working Directory** | The folder where you are currently editing files. | This is where you create, update, or delete project files before Git saves those changes. |
| **Staging Area** | A preparation area for changes you want to save. | This lets you choose which changes should go into your next commit. |
| **Local Repository** | The Git history stored on your own computer. | This stores your commits, branches, and project history locally. |
| **Remote Repository** | A shared copy of the project hosted online or on a network. | This lets teams share code by pushing and pulling changes. |
| **Branches** | Separate versions of the project. | This lets you work on a feature or fix without changing the main version right away. |
| **Pull Request** | A request to review and merge changes from one branch into another. | This helps teams discuss, review, and approve code before it becomes part of the main project. |
| **Merge** | Combining changes from one branch into another branch. | This brings completed work back into the main project history. |

## Basic Git Workflow

| Step | What happens |
| --- | --- |
| **1. Edit files** | You make changes in the working directory. |
| **2. Stage changes** | You choose which changes should be included in the next commit. |
| **3. Commit changes** | You save a snapshot of the staged changes to your local repository. |
| **4. Push changes** | You send your commits to a remote repository so others can access them. |
| **5. Open a pull request** | You ask teammates to review your changes before they are merged. |
